## v2.2.1（2026-10-04 19:09:08）清理：logo 改为远程取，仓库不再存图片

> 项目：**OnOB站通知订阅工具**（OnO Bilibili Notifier，缩写 **OnOBN**）

**改了什么**

### 1. 移除随包图片文件夹，logo 改为远程取

`src/static/webuiimg/`（里面就一张 851x198 的白色透明底 `logo.png`）整目录删除，
**仓库里现在一个图片文件都没有**。运行时由 `/api/brand/logo` 给出地址。

- **默认取作者的仓库图**：`cdn.jsdelivr.net/gh/XxBoLuoxX/xxboluoxx.github.io@main/images/logo.png`
  - ⚠️ 为什么是 jsDelivr 而不是 `raw.githubusercontent.com`：指向的是**同一个仓库、
    同一分支、同一张图**，但实测 raw 域名 20 秒超时取不到（国内常被拦），
    jsDelivr 是 GitHub 的公共 CDN 镜像，1.3 秒返回 9430 字节。
  - 想换回官方 raw 或自己的图：设环境变量 `ONOBN_LOGO_URL`。
  - 想彻底不显示（离线部署、或不想让浏览器往外发请求）：`ONOBN_LOGO_URL=off`，
    接口直接返回 404。
- **自定义图仍然优先**：把 `logo.png` 放进数据目录的 `images/ui/` 就盖住远程地址
  （这个目录跟数据一起活，换新版不会被删）。
- **取不到图不会出问题**：前端是探测式加载，CSS 里 `--logo` 默认 `none`，
  只有图片真的 `onload` 才设上 URL；远程失败触发 `onerror`，保持 `none`
  —— 不显示、不报错、**不留空白块**，断网照样正常用面板。

### 2. 修复：playwright 被误降级为可选

`requirements-optional.txt` 相应清空（目前没有可选依赖），保留文件作占位。

## v2.0.4（2026-10-04 09:00:00）小更新：修复点「🔄 刷新」报 renderHero is not defined

> 项目：**OnOB站通知订阅工具**（OnO Bilibili Notifier，缩写 **OnOBN**）

**症状**
- 面板上点「🔄 刷新」（概况页 / 运行状态页都有这个按钮），弹出红色提示：
  「refresh-state」出错了：renderHero is not defined
- 首屏看着正常，一点刷新才炸，很难联想到是"函数压根不存在"

**根因：一行注释吞掉了两个函数**
- `src/static/app.js` 给 `loadLegacyInfo()` 写说明时**只写了 `/*`、没写收尾**，
  于是从那一行一直到下一个 `*/`（几十行之后）全被当成注释内容：

      735  /* 旧版 data.db —— …新版落盘换成了 JSON，
      736  async function loadLegacyInfo() {   ← 其实是注释，不是代码
      771  function renderHero() {             ← 同上

- 函数**声明**被注释掉不会报语法错误（`node --check` 照样通过），
  只有跑到 `loadState()` 里调用 `renderHero()` 那一刻才炸
- 更阴的一点：`grep renderHero` 能看到**两处**（一处调用、一处"声明"），
  肉眼完全看不出问题 —— 必须真正解析一遍才知道那处声明不在语法树里

**修复**
- 补上注释收尾，并在原地写明"块注释必须成对闭合"的坑
- 新增 `tests/test_js_comment_balance.py` 盯住这类问题（14 项）：
  逐字符扫 JS（跳过字符串 / 模板串 / 正则 / 行注释），`/*` 无收尾直接失败；
  已闭合的块注释里若含整行 `function xxx(` 判定"吞了代码"；
  再用 node 真跑一遍，确认首屏要用的 7 个函数确实在语法树里
- 反向验证：把注释收尾去掉，检查立刻报错，断言咬得住

## v1.95.0（2026-10-02 07:57:21）小更新：删掉最新动态后不再误推旧动态

**修复**
- UP 主删掉最新那条（或撤稿、转私密）后，被删的那条恢复、或接口在两个 ID 之间来回跳时，会把订阅前就存在的旧动态再推一遍：判定「回退为更早的」是对的，但判定之前就无条件把基线时间改成了更早的那条，等于把水位线往下拉，旧内容重新变新
- 日志里会出现互相矛盾的两行：先「回退为更早的，静默不推送」，紧接着又「已推送」，就是上面这条造成的

**优化**
- 基线时间改成只许涨不许跌：判定为「不是新内容」时 ID 照常更新，但保留原来更高的那一档时间
- 回退的那条也记进「已提醒」，水位线之外再按 ID 兜一道

## v1.94.0（2026-10-02 06:54:55）小更新：新动态被置顶后不再重复提醒

## v1.91.0（2026-09-29 09:04:54）小更新：登录没生效时不再一路加速撞墙

**修复**
- B 站登录态失效（`-352` / `-403` / HTTP 412）时，轮询会**一路加速到最快档**：这类失败走的是「登录态」通道，不计入风控次数，于是「很久没撞风控」的判断被误当成「风控已解除」，把间隔从 24s 一路压回 8s。结果是每 8 秒撞一次墙，B 站风控反而更重、更难恢复
- 上一条带来的假日志：满屏 `-352` / `412` 的同时，日志里写着「风控风险已解除，检查频率已回到最快：24s → 8s」—— 其实根本没有解除

**优化**
- 登录态失效期间**冻结自动加速**，并把轮询固定在温和的中间档（30 秒），不快于你设的基线、不超出你设的上限。登录一恢复就自动接着加速，不用改配置
- 这段期间的日志说清是「登录态没生效，已暂停加速」，不再谎报「撞到风控」「风控已解除」；同样 60 秒只报一次，不刷屏

**界面**
- 「概况 → 健康度 → 轮询间隔」在登录态没生效时会标黄并显示「已暂停加速（B站 登录态没生效）」，不再让人以为机器人卡住了

**注意**
- 看到「已暂停加速」就是让你去「⚙️ 凭据 → B站登录」重新扫码 —— 这种情况光调大间隔没用，因为问题不在快慢，在 B 站不认这段 cookie

## v1.89.0（2026-09-28 09:13:00）小更新：启动变慢的三处根因全部修掉

**修复**
- 启动时「清理残留进程」做了**三遍**：`start.py` 里有两块复制粘贴的重复代码，再加一次 `_kill_leftovers()`。Windows 上每趟都要起 PowerShell / wmic 扫全机 python 进程、还要 netstat 查端口，单次好几秒 —— 光"清理自己"就吃掉半分钟，而这部分耗时跟订阅多少、日志多大都无关，纯属浪费
- 判断进程是否还活着时，对**每一个** PID 单独起一次 `tasklist` 子进程：`.bot.pids` 里攒多少个就起多少次，攒到 50 个就是几十秒；而 `kill_ours()` 内部还要跑两遍全机扫描，叠加上面调三遍 —— 六趟扫描全在那儿空转
- 启动同步**完全串行**：每个 UP 依次跑 直播 / 投稿 / 动态 三个请求，跑完再固定睡 0.4 秒。5 个 UP + 3 个合集就是 18 次串行请求，B 站一风控每次都要等满 10 秒超时，光这一步三分多钟，日志停在「机器人已上线」不动，看着像卡死
- `bot.log` 只追加、从不清理，实测攒到 **27 万行 / 9.2MB**；而面板「日志」页每次都要把整个文件读进内存再取末尾 —— 日志越大，面板打开越慢

**优化**
- 启动清理合并成**一次**，全机扫描从 6 趟降到 1 趟
- 进程存活判定改成**批量**：Windows 上一次 `tasklist` 取回全部 PID 再在内存比对；`kill_ours()` 结尾不再重扫一遍全机（改为只写"刚杀过且确认还活着"的，语义不变、零额外开销）
- 启动同步改成**并发**（默认 3 个，可配 `startup_sync_concurrency`），并发本身就是节流，不再逐个 sleep
- 启动同步加**总时限**（默认 25 秒，可配 `startup_sync_budget`）：超预算就停，剩下的交给第一轮轮询补
- `bot.log` 超过 8MB 时启动自动精简，只留最近 2 万行（原子替换，写一半断电也不会丢）
- 面板「日志」页改成**只读文件末尾**，总条数改用字节扫描统计，实测读取从 0.146s 降到 0.020s（约 7 倍），结果完全一致

**注意**
- 启动同步被时限截断时，日志会写明「N 位 UP 主留到第一轮轮询再对齐」—— 这是正常的，轮询里本来就有静默对齐（`_init_baseline`），**不会把历史内容当新内容补推一遍**
- 想让启动同步更从容（订阅很多、网络慢），可在 `config.yaml` 里调大 `startup_sync_budget`；想更激进可加大 `startup_sync_concurrency`（上限 8）
- 日志精简只在 `bot.log` 超过 8MB 时触发，触发时会记一行「已精简：丢掉最早的 N 行」

**新增**

- 保存 cookie 前先求证：B站 明确说无效的**直接不保存**，并说明原因，不再造出一个假的「已登录」
- 机器人每轮把实测结果写进心跳，面板顶栏、健康度、待办都按实测显示；运行时发现失效会汇总成一条告警（10 分钟内只报一次），点明要去重新登录
