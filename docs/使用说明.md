# OnOB站通知订阅工具 · 使用说明

**OnO Bilibili Notifier**（缩写 **OnOBN**）

> 🤖 **代码由 AI 生成**：本项目的程序代码由**腾讯元宝「Hy4 preview」**生成，
> 由作者整理、测试与维护。本项目采用 **MIT License**（宽松开源协议，详见 LICENSE）。

> 面向完全没写过代码的同学。跟着做就行，遇到报错先看最后一章「常见问题」。

这个工具能做什么：你关注某个 B 站 UP 主后，TA **开直播 / 发新视频 / 发新动态 / 动态被置顶评论**时，
机器人在你指定的 QQ 群里发一条带封面、带跳转按钮的提醒卡片。

## 第 1 步：在 QQ 开放平台创建机器人

### 1.1 注册开发者账号

1. 打开 <https://q.qq.com/> ，用 QQ 扫码登录
2. 完成**开发者主体认证**（个人 / 企业都行，按页面提示填姓名身份证或营业执照）
3. 认证通过后，进入「应用管理」→ 点「**创建机器人**」，填名字和头像就创建好了

### 1.2 拿到两个关键凭据

进入刚创建的机器人 → **「开发设置」**，你会看到：

| 名称 | 说明 |
|---|---|
| **AppID** | 一串数字，直接复制 |
| **AppSecret** | 点「生成」按钮才会出现，**只显示一次**，务必立刻复制保存 |

> 忘了 AppSecret 只能重新生成，旧的会立刻失效。

### 1.3 打开群聊权限

在同一个「开发设置」页里，找到**服务范围 / 权限配置**，把**群聊**相关的开关打开
（不同时期按钮名字不一样，看到「群聊」「群消息」就打开）。

### 1.4 把机器人拉进群

1. 用手机 QQ 打开你要接收提醒的群
2. 群设置 → 机器人 → 把你的机器人添加进去
3. **关键一步**：在机器人的设置里打开「**允许机器人主动发言**」
   —— 不开这个，提醒一条都发不出去

### 1.5 让机器人「上线」

机器人状态需要是「**已上线**」。开发中的机器人调用接口会失败。
如果控制台提示配置 **IP 白名单**：

- 本地运行：填你家宽带的公网 IP（百度搜「IP」能看到）
- 云端运行：填服务器的公网 IP

## 第 2 步：本地运行（自己的电脑）

### 2.1 装 Python

- **Windows**：去 <https://www.python.org/downloads/> 下载，安装时**必须勾选
  "Add Python to PATH"**（这个不勾后面会很麻烦）
- **Mac**：自带 Python 3，或 `brew install python3`
- **Linux**：一般自带，`python3 --version` 看看有没有

### 2.2 启动

文件夹里只有 **3 个启动脚本**，别找错了：

| 脚本 | 用途 | 什么时候用 |
|---|---|---|
| **`启动机器人.bat`** | 命令行窗口 + 自动开浏览器 | **日常用这个**（Windows） |
| **`安装依赖.bat`** | 只装依赖，不做别的 | 其它 bat 报 `No module named xxx` 时先跑它 |
| **`启动机器人.sh`** | Mac / Linux | 非 Windows 系统 |

> bat 都是**中文界面**，直接双击即可。

**Windows 用户**：双击 **`启动机器人.bat`**

**Mac / Linux 用户**：在文件夹里打开终端，执行

```bash
./启动机器人.sh
```

第一次运行会自动装依赖（要等一两分钟），之后看到：

```
网页管理面板 → http://127.0.0.1:8088
```

**保持这个黑窗口开着不要关**，关了机器人就停了。

### 2.2.0 新的启动流程（重要）

启动器会**先开网页面板、自动打开浏览器**，让你把 AppID / AppSecret 填好，
**填完保存后机器人会自动连接**——不用手动重启。

你会看到这样的顺序：

```
[1/4] 依赖已就绪
[2/4] 配置文件已就绪
[3/4] 启动网页管理面板（端口 8088）
  ┌────────────────────────────────────────────────┐
  │  管理面板：http://127.0.0.1:8088               │
  │  已尝试自动打开浏览器，没弹出就手动复制上面的地址 │
  └────────────────────────────────────────────────┘

  ⏳ 还没填 AppID / AppSecret，机器人先不启动。
     请在浏览器面板 →「⚙️ 设置」里填写并保存，填好会自动启动。
```

填好保存后：

```
  ✅ 检测到凭据，正在启动机器人…
```

**如果还是打不开网页**，看下面 2.2.2。

### 2.2.1 双击 bat 报错怎么办（Windows 常见）

如果双击后闪出一堆 `'xxx' 不是内部或外部命令`，或者报
`No module named 'botpy'` / `No module named 'flask'`，按下面顺序解决：

**方法 A：先单独装依赖**

双击 **`安装依赖.bat`**，等它跑完（看到"安装结束"），再双击 `启动机器人.bat`。

**方法 B：手动敲命令（最可靠）**

1. 在文件夹地址栏里输入 `cmd` 然后回车（会直接在这个目录打开命令行）
2. 逐条执行：

```bat
python -m pip install -r src/requirements.txt
python start.py
```

如果第一条报网络错误，加清华镜像：

```bat
python -m pip install -r src/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

如果提示权限不足，加 `--user`：

```bat
python -m pip install --user -r src/requirements.txt
```

**方法 C：命令是 `py` 而不是 `python`**

有些电脑装在应用商店版，命令叫 `py`。试试：

```bat
py -3 -m pip install -r src/requirements.txt
py -3 start.py
```

> **强烈建议：把整个文件夹放到不带中文的路径下**，比如 `C:\OnOBN`。
> 路径里的中文（`C:\Users\...\桌面\ai开播提醒机器人\...`）偶尔会引起奇怪的编码问题。

**方法 D：纯英文启动器**


### 2.2.2 打不开网页 / 提示"资源解析服务请求失败"

先确认一件事：**命令行窗口里有没有出现 `Running on http://127.0.0.1:8088`**。

| 情况 | 说明与解决 |
|---|---|
| **没有这行** | 面板根本没起来。把窗口往上翻，看有没有红色报错；或手动跑 `python webui.py` 看报错 |
| **有这行，但浏览器打不开** | 往下看下面几条 |
| **窗口已经被关掉了** | 面板和机器人是一起停的，重新双击 `启动机器人.bat` |

浏览器打不开时，按顺序试：

1. **地址要写全**：在浏览器地址栏（不是搜索框）输入
   `http://127.0.0.1:8088/` —— 注意前面有 `http://`，结尾有 `/`。
   只输 `127.0.0.1:8088` 会被当成搜索词，就会报"资源解析服务请求失败"。

2. **换浏览器**：用 Edge 或 Chrome，别用 QQ 浏览器 / 某些内置浏览器。

3. **换 localhost 试试**：`http://localhost:8088/`

4. **注意端口**：如果 8088 被别的软件占了，启动器会自动换端口。
   看窗口里实际显示的是哪个，比如 `http://127.0.0.1:8089`。

5. **关掉代理 / VPN**：某些代理会把本地地址也拦掉。

6. **杀毒软件**：极少数情况下会拦本地监听，临时关掉试试。

### 2.3 打开管理面板

浏览器访问 <http://127.0.0.1:8088>，看到的就是配置界面。

> 面板右上角有个 🌙/☀️ 按钮，可以切换**暗夜 / 日间**模式，
> 默认是跟着你电脑的系统主题自动变的。

## 第 3 步：用网页面板配置订阅

### 3.1 填机器人凭据

面板最下面「**⚙️ 设置**」里：

- AppID：填第 1.2 步拿到的
- AppSecret：填第 1.2 步拿到的（填完保存后输入框会清空，不会回显）
- 其他保持默认

点「保存设置」，然后**重启机器人**（回到黑窗口 Ctrl+C，再启动一次）。

### 3.2 确认群被登记了

面板「📋 订阅管理」里应该能看到你的群。
如果看不到：

- 把机器人重新拉进群一次，或
- 在群里 @机器人 发一条「帮助」

群出现后，可以给群起个名字（点群名就能改）。

### 3.3 添加订阅

面板「➕ 添加订阅」：

1. 目标群：选要接收提醒的群
2. UP 主 UID：填数字。UID 在哪看？打开 UP 主主页，网址长这样
   `https://space.bilibili.com/672328094`，最后那串数字就是 UID
3. 点「查询」→ 确认显示的名字对得上
4. 勾选要默认开启的提醒（直播 / 视频投稿 / 动态）
5. 点「添加订阅」

### 3.4 精细设置开关

在「📋 订阅管理」里，每个 UP 主一行，每行有三组开关：

| 开关 | 作用 |
|---|---|
| 滑块 | 这个群要不要收这一类提醒 |

**举例**（就是你要的效果）：

- 1 群订阅了 A：只把「直播」滑块打开 → 只有开播才提醒
- 2 群订阅了 A：把「直播」和「动态」都打开 → 开播和发动态都提醒

每个群、每个 UP 主、每一类都是**独立**的，互不干扰。

### 3.5 测试一下

面板「📤 测试推送」选个群点「发送测试」，群里应该立刻收到一张测试卡片。
收到就说明链路通了。

### 3.6 一键自检

面板「🩺 一键自检」填个 UID 点开始，会告诉你：

- B 站接口通不通（能不能查到直播/投稿/动态）
- 机器人凭据对不对

哪一项显示失败，按提示处理即可。

## 第 4 步：部署到云端服务器（可选 · 未测试）

> ## ⚠️ 这一整章未经测试
>
> 以下内容是**理论上的可行方案**，作者从未在真实的服务器环境上跑通过。
> 你按着做可能一路顺利，也可能在某个环节卡住——卡住的话欢迎反馈，
> 但请先有心理准备：这一章不属于"跟着做就行"的范畴。
> 如果只是想稳定常驻，**Windows 上开着电脑跑同样可以 7×24**，这是验证过的方案。

本地运行的问题是**电脑关机就停了**。要 7×24 小时运行，需要放到服务器上。

### 4.1 准备服务器

- 买一台云服务器（腾讯云轻量 / 阿里云 ECS 都行，最便宜的配置就够）
- 系统选 **Ubuntu 22.04**
- 记下服务器的**公网 IP**

> ⚠️ 回到 QQ 开放平台，把这台服务器的公网 IP 填进 **IP 白名单**，
> 否则机器人调用接口会被拦。

### 4.2 上传代码并运行

用 SSH 连上服务器后执行：

```bash
# 装 Python 环境
sudo apt update && sudo apt install -y python3 python3-pip

# 上传代码（在你自己电脑上执行 scp，或用 FinalShell 等工具拖上去）
# scp -r OnOBN root@你的服务器IP:/root/

cd /root/OnOBN
pip3 install -r src/requirements.txt
cp docs/config.example.yaml config.yaml
```

### 4.3 后台常驻运行

**方式一：最简单（nohup）**

```bash
nohup python3 start.py > bot.log 2>&1 &
```

断开 SSH 也不会停。看日志：`tail -f bot.log`

**方式二：用 systemd（推荐，开机自启 + 崩溃自动重启）**

创建 `/etc/systemd/system/OnOBN.service`：

```ini
[Unit]
Description=B站提醒机器人
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/OnOBN
ExecStart=/usr/bin/python3 /root/OnOBN/start.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

然后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable OnOBN     # 开机自启
sudo systemctl start OnOBN      # 启动
sudo systemctl status OnOBN     # 看状态
sudo journalctl -u OnOBN -f     # 看日志
```

### 4.4 在云端怎么打开管理面板

面板默认只监听 `127.0.0.1`（只能服务器本机访问），这样最安全。三种访问方式：

**方式 A：SSH 隧道（最安全，推荐）**

在你自己电脑的终端执行：

```bash
ssh -L 8088:127.0.0.1:8088 root@你的服务器IP
```

然后本地浏览器打开 <http://127.0.0.1:8088>，就像在本地一样。

**方式 B：直接暴露到公网**

```bash
python3 webui.py --host 0.0.0.0 --port 8088
```

然后浏览器访问 `http://服务器IP:8088`。
**用这种方式一定要做两件事**：

1. 在服务器防火墙/安全组里放行 8088 端口
2. 在面板「设置」里填一个**面板访问口令**（否则任何人都能改你的配置）

**方式 C：用 Docker**

```bash
cd OnOBN
docker compose up -d
```

### 4.5 云端特别注意事项

| 事项 | 说明 |
|---|---|
| IP 白名单 | 服务器公网 IP 必须加到 QQ 开放平台的白名单 |
| 服务器 IP 变动 | 换了服务器要去白名单里更新 IP |
| 日志 | 出问题先看 `bot.log` |
| 配置修改 | 面板改完订阅**立即生效**；改 AppID/Secret 需要重启机器人 |

## 安全设置（重要）

> ⚠️ **这些安全功能从未实际测试过。**
> 下面每一条防护都**只验证过「功能能跑通」**（比如设了口令确实要登录、
> 连错 5 次确实会锁定），**从未经过真正的安全测试、渗透测试或代码审计**。
> 能跑通 ≠ 挡得住攻击。请不要在需要真实安全防护的场景下依赖它们，
> 更不要把面板直接暴露到公网。发现可疑之处请务必反馈。

你担心影响本地或服务器，这部分就是为此写的。程序做了这些防护：

### 默认就是安全的

| 项目 | 默认状态 |
|---|---|
| 面板监听地址 | `127.0.0.1` —— **只有本机浏览器能打开**，局域网和公网都访问不到 |
| 访问口令 | 未设置（本机使用无需口令） |
| 对外暴露 | 若强行改成 `0.0.0.0` 且没设口令，**面板会拒绝启动** |
| 配置文件权限 | 保存时自动收紧为仅本人可读写 |

所以**日常使用不用做任何额外配置**，双击启动就是安全状态。

### 已内置的防护措施

**1. 防止面板被外人访问**

- 启动时检查监听地址：绑定 `0.0.0.0` 却没有口令 → 直接拒绝启动并给出解决办法
- 即使设了口令并对外，也会打印提醒，建议改用 SSH 隧道

**2. 防止口令被暴力破解**

- 连续输错 5 次 → 锁定 60 秒，之后再犯锁定时间翻倍（最长 1 小时）
- 每次登录成功/失败都记进 `security.log`，面板「🛡️ 安全」卡片能看到

**3. 口令不会明文保存**

- 面板里输入的口令会用 **pbkdf2（12 万次迭代）哈希**后再写进 config.yaml
- 配置文件里只会看到 `pbkdf2$...` 这样的串，看不到原口令
- 忘了口令？执行 `python security.py --hash 新口令`，把输出那行替换进 config.yaml

**4. 防止跨站伪造请求（CSRF）**

- 所有修改类接口都要求特定请求头，别人的网页无法偷偷改你的配置
- Cookie 设为 `httpOnly` + `SameSite=Strict`

**5. 防止恶意输入**

- UID 只接受纯数字；群标识只接受字母数字和 `_` `-`
- 文件路径被限制在项目目录内，`../../etc/passwd` 这类穿越会被拒绝
- 配置文件只接受白名单字段，无法被塞进任意配置

**6. 防止恶意图片地址（SSRF）**

- 提醒卡片里的图片只放行 B 站自己的图床域名，其他地址一律丢弃

**7. 密钥不会泄进日志**

- 日志里的 secret / token / cookie 会自动打码成 `***`
- 群标识只打印前 8 位

### 想远程管理，怎么做最安全？

**推荐：SSH 隧道**（面板仍然只监听本机，最安全）

在你自己电脑的终端执行：

```bash
ssh -L 8088:127.0.0.1:8088 用户名@服务器IP
```

然后本地浏览器打开 `http://127.0.0.1:8088`，效果和在本地一样。

**不推荐但可行：直接暴露**

1. 先设口令：面板「🛡️ 安全」卡片里设置，或
   `python security.py --hash 你的口令` 后写进 config.yaml
2. 再启动：`python webui.py --host 0.0.0.0 --port 8088`
3. 服务器上用防火墙只放行你自己的 IP

### 一键安全体检

```bash
python security.py --check
```

会逐项告诉你：面板暴露面、口令是否哈希存储、配置文件权限、数据文件位置等，
有问题的项会明确标出来。运行 `python check.py` 也会带上这段体检。

### 生成口令哈希

```bash
python security.py --hash 你的口令
```

输出类似：

```
web_password: "pbkdf2$120000$7197377ab97b944c97..."
```

把整行粘进 config.yaml 即可。

### 万一忘了口令

1. 用编辑器打开 config.yaml，删掉 `web_password` 那一行
2. 重启面板 → 免登录进入
3. 再到「🛡️ 安全」卡片重新设置

### 还有几点建议

- **不要把整个文件夹上传到公开仓库**：`.gitignore` 已排除 config.yaml / data.json，
  但如果你手动改过，注意别把含 AppSecret 的 config.yaml 提交上去
- **服务器只开需要的端口**：机器人是**出站连接**（WebSocket），
  不需要在防火墙开任何入站端口；只有你想远程开面板才需要开端口
- **AppSecret 泄露了就重新生成**：开放平台点「重置」，旧的立刻失效

## 安全加固

### 已加的加固措施

| 措施 | 作用 |
|---|---|
| **安全响应头** | CSP、`X-Frame-Options: DENY`（禁止被嵌 iframe）、`nosniff`、`no-store` |
| **全局限流** | 单 IP 写请求 120/分钟、读请求 300/分钟 |
| **自动封禁** | 反复触发限流的 IP 自动封禁 1 小时，面板可一键解封 |
| **请求体限制** | 256KB 上限，挡住超大 payload |
| **文件完整性自检** | 记录代码哈希快照，之后文件被改动会立刻发现 |
| **凭据落盘混淆** | config.yaml 里的 AppSecret / B站cookie 以 `enc1:` 密文保存 |

面板「🛠️ 加固状态」卡片能看到被封 IP、限流阈值，点「建立基准」记录代码校验值。

### 关于「混淆 / 无源码版本」

> ⚠️ **已经移除**：`tools/obfuscate.py`（一键混淆工具）已于 v2.2.0 删除。
>
> 原因：本项目决定只发布**源码可读**的版本，不再出混淆版 ——
> 混淆会删掉源码里的注释，而那些"为什么这么写"的说明正是这个项目最值钱的部分；
> 而且混淆版没法跑全量回归，出问题无从排查。
>
> 如果你确实需要对外分发时不暴露实现细节，正确做法是**只分发必要的运行文件**，
> 或者干脆不分发 —— 本项目本就是给自己用的桌面程序。

### 顺手能做的几件事

- 文件夹不要放在共享目录、网盘同步目录里
- 不用时关机或退出，别长期挂在无人看管的机器上
- 发现 AppSecret 泄露，立刻去开放平台重置（旧的马上失效）

## 日志页（自动翻译，排障首选）

后台日志里混杂着英文报错、aiohttp 警告、B 站和 QQ 的错误码，
看不懂很正常。日志页会**自动做三件事**：

**1. 归类** —— 判断这条属于哪个部分（按 `文件名:行号` 判断，很准）：

🤖 机器人 · 📺 B站接口 · 🖥️ 管理面板 · 🔑 B站登录 · 🌐 网络请求 ·
📦 依赖安装 · ⚙️ 配置文件 · 💾 数据存储 · 🛡️ 安全加固

**2. 翻译成中文** —— 例如：

| 原始日志 | 翻译 |
|---|---|
| `object has no attribute '_reload_cookie'` | 代码版本不一致：新代码调用了旧版本里还没有的功能 → **请完整替换成最新文件后重启** |
| `code=-352` | B 站风控拦截 → **去「🔑 B站登录」用「🌐 浏览器登录」重新登录** |
| `appid invalid` | AppID 填错了 → **去开放平台核对** |
| `Unclosed client session` | 有网络连接没正常关闭（小疏漏，不影响功能）→ **可忽略** |
| `No module named 'botpy'` | 缺少依赖包 → **双击「安装依赖.bat」** |

**3. 汇总** —— 顶部显示健康度徽章（✅ 正常 / ⚠️ 有警告 / ❌ 有错误），
按部分统计错误数，并把「需要关注的问题」单独列出来，每条都带解决办法。

顶部还能筛选：只看错误 / 错误+警告 / 只看能看懂的（已翻译）。
可以关掉「自动刷新」和「显示翻译」（想看原始日志时）。

日志现在会写入 `bot.log` 文件，所以机器人这边的输出面板也能看到
（以前 botpy 只往控制台打，面板读不到）。

## 常见问题

### 命令行报 `appid invalid`（错误码 100007）

意思是 **AppID 不对**，平台不认。按顺序排查：

1. AppID 是不是抄错了？它是**纯数字**（形如 `1020xxxxxx`），不含空格、引号或字母
2. 确认填的是**这个机器人**的 AppID，不是别的机器人、也不是别的应用的
3. 面板「⚙️ 设置」里如果勾了「沙箱环境」，先取消勾选试试
4. 改完保存，**不用关窗口重启**，启动器检测到凭据变了会自动重试

> 旧版启动器遇到这个错误会直接整个退出，连面板一起关掉，结果没地方填配置。
> 现在改成：面板照常开着，你在面板里改完保存，机器人自动重连。

### 填 AppID 时输入框自己变回示例值

**v0.7.2 已修复，请更新到最新版。**

原因：面板每 15 秒轮询一次状态，会无条件把服务端的值回填到输入框，
而自动生成的 config.yaml 里写死了示例值 `1020xxxxxx`。
所以你刚敲进去的 AppID，最多 15 秒就被刷回去了。

现在的保护机制：

- 你一改动输入框（哪怕只是点进去），轮询就**不再覆盖它**
- 保存成功后才解除保护，让真实值同步回来
- 输入框下方有「当前已保存：xxx」，随时能核对
- 想放弃改动，点「↺ 恢复已保存」

如果你手上还是旧版本，临时办法：**填完立刻点保存**，别等它轮询。

### 启动失败 / 退出码是什么意思

启动脚本失败时会**保留面板不关**（好让你进去改凭据），并写明退出码含义：

| 退出码 | 含义 | 怎么办 |
|---|---|---|
| 2 | 依赖没装好 | 双击「**安装依赖.bat**」 |
| 3 | 面板起不来 | 端口被占用 / 已有实例在跑，关掉其它窗口再试 |

另外 v0.9.0 起会**自动复用已在运行的面板**（检测到 8088-8099 有面板就直接连过去），
不再重复启动导致端口冲突——这是窗口闪退最常见的原因。

错误详情可查 `bot.log`。

### 页面上按钮点了没反应

**v1.1.0 修好了根因。**

app.js 顶层有大量 `$('xxx').onclick = ...`，而 `$()` 以前直接返回 null。
**只要页面少一个元素，整段脚本就在那里抛错并停止** ——
后面所有按钮、页签、初始化全部失效。「去填写」点不动就是这个原因。

现在元素缺失只警告、不中断，其它功能照常。

> 更新后请 **Ctrl + F5** 强制刷新一次，否则浏览器还在用缓存的旧 JS。

### bat 报错「'ho.' / 'errorlevel' 不是内部命令」（已修复）

**v1.4.1 修复。**

根因：bat 用 LF（\n）换行，而 cmd.exe 靠 **CRLF（\r\n）** 定位行。
LF-only 会让 cmd 行错位，跳到某行中间执行，把命令劈成碎片。

修复：四个 bat **以二进制重写，强制 CRLF**，且内容改为**纯 ASCII**
（中文交给 Python 输出）。新增 `safe_print()`，在 GBK 控制台上
把 emoji 换成 `[OK]` `[X]` 标记，不崩也不变问号。

### bat 乱码 / 命令被劈碎（如 'Windows' 不是内部命令）

**v1.4.0 已彻底修复。**

根因：bat 用 UTF-8 编码写，但 cmd 读 bat 时按 **GBK** 解析。
UTF-8 中文 3 字节、GBK 2 字节，字节错位会把整行命令劈碎，
中文也全变成「锟斤拷」。

修复：四个 bat **全部改用 GBK 编码**重写（cmd 怎么读就怎么写），
且 bat 里不放 emoji；`safe_stdio()` 改为区分控制台与文件：
控制台跟随 GBK（中文正常），文件用 UTF-8（日志完整）。

### 启动就崩 / emoji 导致 UnicodeEncodeError

**v1.1.1 已修复。**

报错长这样：

```
UnicodeEncodeError: 'gbk' codec can't encode character '\U0001f6e1'
```

`\U0001f6e1` 就是 🛡️。Windows 中文环境默认编码是 **GBK，表示不了 emoji**，
程序一打印带 emoji 的那行就崩溃。「锟斤拷」也是同一原因。

修复：所有入口启动时把输出重配置为 UTF-8（失败则替换不可编码字符，绝不崩），
四个 bat 也统一加 `chcp 65001` + `PYTHONIOENCODING=utf-8`。

### 关掉了端口还是被占用（端口一直往后跳）

**v1.1.1 已修复。**

start.py 会再起 webui.py 和 bot.py；以前只杀 start.py，
这两个「孙进程」还活着，端口一直被占，所以每次启动端口都往后跳
（8088 → 8089 → … → 8092）。

现在退出时会连子进程一起杀（Windows 用 `taskkill /F /T`），
并清理端口文件。

**如果你现在就有很多残留进程**：打开任务管理器，
结束所有 `python.exe` / `pythonw.exe` 再重新启动。

### 面板地址连不上 / 连到了别的程序

**v1.1.0 起读取真实端口文件。**

以前靠扫 8088-8099 猜端口，可能连到别的程序上。
现在启动器会把真实地址写进 `.panel_url`，不会再连错。

### 二维码还没扫就提示错误

**v1.1.0 已修复。** 原因是接口只等 4 秒，网络慢时二维码还没生成就返回了，
前端只能显示"获取失败"。现在等待放宽到 15 秒，且会区分
"还在获取中"（自动重试）和"真的失败"。

### 运行日志里全是 HTTP 请求

**v1.1.0 已过滤。** 面板自己每隔几秒轮询一次，Flask 会把这些记录写进日志，
把真正有用的信息淹掉。现在这类行以及 aiohttp 的 Unclosed 警告都会被滤掉。

### @机器人 不登记群（已修复）

**v1.0.0 修好了。根因是代码 bug，不是玄学。**

```python
if name and not g.get("name"):   # ← save() 写在这个 if 里面
    g["name"] = name
    self.save()
```

@机器人 时不会带群名，`name` 是空的 → **`save()` 从不执行** →
群只存在于机器人进程的内存里，从没写进磁盘。而面板是**另一个进程**，
从磁盘读，所以永远看不到。

现在无论有没有名字都会落盘。

### 为什么面板不显示我的群（群列表为空）

**这不是 bug，是腾讯官方的限制。**

腾讯官方机器人**没有提供「获取机器人所在群列表」的接口**，
机器人无从知道自己被拉进了哪些群，所以面板不可能自动列出。

登记群只需做一次，三种方式任选：

| 方式 | 操作 |
|---|---|
| **@机器人 发任意消息**（推荐） | 在群里 @机器人 说「你好」，群就自动出现了 |
| **发「登记」指令** | @机器人 发 `登记`，它会回显本群 ID |
| **手动粘贴群 ID** | 面板「💬 登记群」卡片；群 ID 在机器人日志里有（`group_openid=xxx`） |

登记过一次后，这个群就永久在列表里了。

### 命令行报「获取token失败」

和上面是同一类问题，看窗口里 `[ERROR]` 那一行的具体错误码：

| 错误提示 | 含义 | 怎么办 |
|---|---|---|
| `appid invalid` | AppID 填错 | 见上一条 |
| `secret invalid` / 100008 | AppSecret 填错或已失效 | 去开放平台重新生成（旧的会立刻失效） |
| 没有任何错误码，直接连接超时 | 网络不通 | 检查网络；确认没走异常代理 |
| 提示 IP 不在白名单 | 服务器 IP 没登记 | 去开放平台把当前公网 IP 加进白名单 |

拿不准就运行 `python check.py`，它会逐项告诉你卡在哪一步。

### 开放平台显示在线，但面板显示「机器人未运行」

这是**面板判断方式**的问题，不是机器人真的没跑。

旧版本用 `pgrep` 命令去查进程，而 **Windows 根本没有 pgrep**，
所以永远显示「未运行」——哪怕机器人其实好好在线。

现在改成了**心跳机制**：机器人每 10 秒写一次 `.bot_heartbeat` 文件，
面板读这个文件判断，跨平台且准确。面板顶部新增了「📡 运行状态」卡片，会显示：

- 在线 / 离线，以及最后一次心跳距今多久
- 已登记群数、订阅 UP 主数、已检查轮次、已推送提醒数
- 运行时长、最后推送时间、错误次数

**这里的在线状态和 QQ 开放平台显示的是一致的。**

如果仍然不一致，只有一种可能：**机器人不是由本面板的启动器拉起的**。
比如你单独开了个窗口跑 `python bot.py`，它是能正常工作的，
但面板没启动，或者启动的是另一份。改用「启动机器人.bat」或 `python start.py` 即可。

> 顺带一提：机器人每 10 秒更新一次心跳，所以刚启动时要等几秒面板才会变成「在线」。

### 报 `code=-352 msg=-352`（B 站风控）

**这是最常见的问题，原因是没登录。**

B 站的投稿和动态接口现在强制要求登录态，没带 cookie 就会返回 -352。
直播接口一般不受影响，所以你会看到「直播能查，投稿/动态查不到」。

**解决办法：扫码登录。** 面板 →「🔑 B 站登录」→ 点「扫码登录」→
用 B 站 App 扫二维码确认。登录成功后 cookie 自动保存，**不用重启机器人**，
下一轮轮询就会自动生效。

也可以在命令行登录：

```bash
python bili_login.py
```

终端里会画出二维码，扫码后自动写进 config.yaml。

#### cookie 时效

| 项目 | 说明 |
|---|---|
| 有效期 | 约 **1 个月**（B 站 SESSDATA 的默认时长） |
| 查看剩余时间 | 面板「🔑 B 站登录」卡片，会显示「有效期至 XXXX-XX-XX（还剩 N 天）」 |

面板上还会显示「获取于 XXXX-XX-XX」，方便你判断用了多久。

#### 扫码不成功怎么办

用**手动粘贴**兜底：

1. 浏览器打开 bilibili.com 并登录
2. 按 F12 打开开发者工具 → Network（网络）
3. 随便点一个请求 → 在 Request Headers 里找到 `Cookie` 那一行

### 群里收不到任何提醒

按顺序排查：

1. 群设置里有没有开「**允许机器人主动发言**」（最常见的原因）
2. 面板上的「机器人运行中」徽章是不是绿色的
3. 面板「📤 测试推送」能不能发成功
4. 面板「🩺 自检」看机器人凭据是不是有效
5. AppID / AppSecret 改过之后有没有重启机器人

### 面板里看不到我的群

群只在机器人**收到过事件**后才会登记。把机器人重新拉进群，或在群里 @它发一条消息。

### 提醒发了但没有图片

图片走的是「Markdown 内嵌图片」，需要能被 QQ 服务器下载。
如果图片一直出不来，去面板「设置」里把「提醒带图片」关掉，就只发文字和按钮。

### 提醒不够醒目怎么办

群消息很容易被免打扰吃掉。几种改善方式：

- **分层订阅**：只给真正在意的 UP 主开提醒，减少噪音
- **私聊推送**：让关心的人单独订阅，私聊不受群免打扰影响
- **文案模板**：在面板里把提醒文案改得更抓眼

### 动态老是查不到 / 报错

动态接口对未登录请求比较严格。解决办法：

1. 浏览器登录 B 站，F12 → Network → 随便找个请求 → 复制 Request Headers 里的 `Cookie`
2. 把整串 Cookie 粘到面板「设置」→「B 站 Cookie」里保存
3. 重启机器人

### 投稿/动态提醒延迟

投稿和动态默认**每 3 分钟**才查一次（直播是 1 分钟一次），这是为了省请求、防限流。
想更快的话，把「设置」里的「投稿/动态检查频率」调成 1（但别把轮询间隔调到 30 秒以下，
容易被 B 站限制）。

### 一订阅就收到一堆历史提醒？

不会。订阅时会先记录当前状态作为基线，只有**之后**的新内容才会提醒。

### 数据存在哪

`data.json`。改群名、开关都实时写进去。备份这个文件就等于备份全部配置。

### 想换台机器跑

把整个文件夹（尤其是 `config.yaml` 和 `data.json`）复制过去，
装好依赖直接启动即可。

## 凭据存放在哪里？（换版本前必看）

你每次都是「解压覆盖整个文件夹」，所以搞清楚凭据在哪很重要。

| 数据 | 存放位置 | 说明 |
|---|---|---|
| **AppID / AppSecret** | `config.yaml` 第 5、6 行 | secret 会以 `enc1:` 密文保存 |
| **B站 cookie** | `config.yaml` 的 `bili_cookie` | 同样是密文 |
| **面板口令** | `config.yaml` 的 `web_password` | 存的是哈希，不是明文 |
| **解密密钥** | `.machine_key`（隐藏文件） | 和 config.yaml 同目录，**别删** |
| **群和订阅** | `data.db` | SQLite 数据库，**别删** |

### 换新版时怎么保住凭据

**推荐做法（最省事）**：直接解压覆盖。只要不删下面这几个文件，
凭据和订阅都在：

- `config.yaml`
- `.machine_key`
- `data.db`

**稳妥做法**：换版本前先备份。

1. 在旧目录双击 **`备份凭据.bat`**
   → 生成 `凭据备份.json`（含 AppID / cookie / 口令）
2. 解压新版后，把 `凭据备份.json` 放进新目录
3. 双击 **`恢复凭据.bat`**
   → 自动写回 `config.yaml`，不用重新填

> ⚠️ `凭据备份.json` 是**明文**，别发给别人，用完可删。

### 什么时候才需要彻底重来

只有当我明确提醒「请删除旧文件夹重新解压」时才需要。那种情况下：

1. 先跑 `备份凭据.bat`
2. 复制 `data.db`（群和订阅都在里面）
3. 删除旧文件夹，解压新版
4. 放回 `凭据备份.json` + `data.db`，跑 `恢复凭据.bat`

## 谁可以用机器人指令

**只有群主和群管理员**。普通成员 @ 机器人或发指令，机器人**完全不理**，
不给任何回复（日志里会记录，但不打扰群）。

### 为什么不用「白名单填 ID」

早期版本提供过「超级管理员 ID 白名单」作为兜底，v1.20.0 已移除。
原因是它依赖 `member_openid`，而官方文档明确写了：

> 相同 bot 在不同的群，获取到同一个用户在群内的唯一识别号 openid
> **不一样**，称为 member_openid

也就是**换群就换一张脸**，名单得重新填。而群主/管理员身份
**天然按群生效**，换群不用管，更省心也更准。

另外官方出于隐私**不提供真实 QQ 号**，`union_openid` 需特殊申请，
所以没有比「群内角色」更可靠的身份依据。

### ⚠️ 前提：要开通「获取群成员」接口

角色来自官方接口
`GET /v2/groups/{group_openid}/members/{member_openid}` 的 `member_role` 字段。

**没开通该接口的话，谁都用不了 —— 包括群主本人。**

排查：在群里发 `/我的ID`，看「群内角色」：

- 显示「群主」或「管理员」→ 正常，可以直接用指令
- 显示「未知」→ 接口没开通，去开放平台开通后重试

> 补充：botpy 的 `GroupMessage.author` 只暴露 `member_openid`，
> 把官方事件里本来带有的 `member_role` 字段丢掉了，所以必须查接口。

### 关于"改昵称冒充"

不成立。机器人**从来不用昵称判断身份**，只认平台下发的角色。
群成员改昵称改不了自己在群里的角色。

## 消息样式：Markdown 没申请权限怎么办

自定义 Markdown 需要申请权限。没申请时有两个选择：

**方案 A（推荐）**：面板「⚙️ 设置」→ 勾选
**「纯文本消息（Markdown 没权限时勾）」**
→ 自动保存，之后所有消息都用 Unicode 符号排版，依然好看：

```
🔴 开播提醒
【直播订阅】"UP"开播啦！记得看噢~
│ 分区　虚拟主播
│ 人气　1,234
```

**方案 B**：什么都不用做。Markdown 发送失败时会**自动降级**成上面的
纯文本，不会让你收不到提醒。

不想看到那堆 `**` 和 `>` 的话，用方案 A。
