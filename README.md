# OnO Bilibili Notifier（OnOBN）

> 中文名：**OnOB站通知订阅工具**　|　英文名：**OnO Bilibili Notifier**　|　缩写：**OnOBN**
>
> 当前版本：**v2.3.6** · 下载请到仓库 **Releases**（成品版含启动脚本，导出版为纯源码）

一个跑在自己电脑上的 B 站更新提醒机器人：订阅的 UP 主**开播 / 投稿 / 发动态 / 发置顶评论**时，自动往指定的 QQ 群推送提醒。自带网页管理面板，订阅、文案、图片、备份都在面板里点几下搞定。

> 🤖 它是 [QQ 开放平台](https://q.qq.com)（腾讯官方机器人平台）机器人的程序，通过官方 SDK `qq-botpy` 走官方 WebSocket 网关与 REST API 收发消息。**不是** go-cqhttp / Mirai 之类的第三方协议实现，也不需要挂个人 QQ 号。

## ⚠️ 使用前必读（三条重要声明）

1. **服务器端从未实测。** 从开发到日常使用，全程只在 **Windows 桌面环境**验证。Linux / macOS / Docker / 云服务器部署均未实测，不保证能跑通。遇到问题欢迎反馈——那部分确实还没人趟过。
2. **代码由 AI 生成。** 程序代码由腾讯元宝「**Hy4 preview**」（AI）生成，由作者「**波萝Buono**」提出需求、整理、测试并持续维护。
3. **安全功能只验过功能能跑通，未做过安全审计。** 面板访问口令、凭据加密落盘等只验证了「能用」，**没有经过任何安全审计或渗透测试**。面板默认只监听 `127.0.0.1`（本机可访问，局域网和公网都访问不到），**不要**改成 `0.0.0.0`；需要远程管理请用 SSH 隧道。

## 它是基于什么运行的

| | 说明 |
|---|---|
| 运行方式 | 用官方 SDK **qq-botpy** 连接 QQ 开放平台，走官方 WebSocket 网关接收事件、官方 REST API 发消息；部分接口由项目自行封装直连 |
| 协议性质 | **官方接口**，不涉及逆向、模拟或非官方客户端协议 |
| 账号要求 | 在开放平台创建机器人，拿到 **AppID / AppSecret**；不需要挂自己的 QQ 号，也不会读取私人聊天 |
| 触达方式 | 机器人被拉进群后可向该群推送；群里 @ 机器人一句话即可自动登记该群 |
| 部署限制 | 官方接口有 **IP 白名单**、被动回复时效、主动推送频率等限制；能力边界与频控以[官方文档](https://bot.q.qq.com/wiki/develop/api-v2/)与公告为准 |

**官方机器人 vs 第三方协议实现**（go-cqhttp / Mirai / Lagrange 等）的关键差别：前者用独立机器人身份、合规、不封号，但只能做官方开放的事，且要申请审核、受频控约束；后者挂个人 QQ 号、能力近似真客户端，但违反 QQ 用户协议、有封号风险、协议一变就集体失效。

本项目要做的事很单纯：**B 站有更新 → 往指定 QQ 群推一条消息**，完全在官方能力范围内，所以只对接官方，不提供也不打算提供第三方协议支持。需要撤回、取全量群成员、发语音等能力的，请去看 [NoneBot](https://github.com/nonebot/nonebot2) 这类生态。

> 平台能力是**逐步开放**的（群管理、群信息、@全体、指令面板等陆续上线），旧文档里「官方没给就没有」的说法已不准确。本项目接入到哪一步，见下一节。

## 平台新开放的群聊能力，本项目适配到哪一步

腾讯机器人在 2026 年陆续开放了一批群聊能力。下表把**平台能力**、**本项目的支持状态**、**需要你做什么**分开写，避免把「平台开了」误当成「装上就能用」。

| 平台能力 | 本项目状态 | 前置条件 / 怎么开 |
|---|---|---|
| **群聊 @全体成员**（`<qqbot-at-everyone />`，文本与 Markdown 消息均支持） | ✅ **已接入**，仅用于**开播提醒** | 机器人需为该群管理员（或群主在机器人资料卡 → 机器人权限设置里授予「@全体成员」群管理能力）；**每群每天仅 1 次（自然日）** |
| **获取群基础信息** `GET /v2/groups/{group_openid}/info` | ✅ **已接入**，且 **2.3.6 起凡给人看的位置一律显示群名**，不再裸露 `group_openid` | 该接口是 **11253 白名单机器人**接口；未开通时显示「未命名群 N」，可在面板「群备注」手动起名 |
| **群机器人状态** `GET /v2/groups/{group_openid}/bot_state`（读 `allow_proactive_msg` 等） | ⏳ **未接入** | 同为 11253 白名单接口。权限批下来之前接了也只会静默退回现状；等权限到位再排，且必须做成「拿到就用、11253 就静默降级」 |
| **指令面板 / 自定义菜单** | ⏳ **未接入** | 项目目前用「群里 @ 机器人发指令」的自有交互；面板能力暂不依赖 |
| **群管理能力**（禁言、入群审批等）、**允许被添加到群聊** | ➖ 平台侧开关，与代码无关 | 在机器人资料卡 / 管理端设置，属于**使用范围与群内权限**，不等于接口权限 |

### @全体成员：怎么用、为什么有时「没用」

在「⚙️ 设置」打开「**开播提醒 @全体成员**」后，默认把标签合并进那张 Markdown 开播卡片一起发，群里只多一条消息。若平台拒收（不是管理员 / 当天额度用完），程序会**去掉标签重发同一张卡片**，提醒不会丢，并记 30 分钟冷却。关掉「合并进卡片」开关可回到已验证可用的「单独一条纯文本 @ + 卡片」双消息模式。

几个最容易踩的点：

- 只限**开播提醒**；下播、投稿、动态、B 站自动发的开播动态都不 @，否则一天额度瞬间耗光
- 测试推送的「**测试也 @全体成员**」默认**关**（每群每天只有 1 次，测试一次就把当天正式开播的额度烧了）；勾了它才会发 @，v2.3.6 起测试成功会同步占掉机器人侧配额
- 配额写在数据目录的 `at_all_quota.json`，跨重启保留、跨天自动重置
- 「机器人资料卡里的群管理能力开关」和「群成员列表里把机器人设成管理员」是两件事；不同客户端落地方式不同，@ 不生效时两条都试，且必须**群主**操作

### 三个「白名单」不是一回事

排查问题时先分清，改错地方会白忙一轮：

| 名字 | 在哪 | 管什么 | 典型报错 |
|---|---|---|---|
| **IP 白名单** | 开放平台 → 开发设置 | 哪台机器能调 OpenAPI | `11298` / `接口访问源IP不在白名单` |
| **白名单机器人** | 平台运营授予的高阶接口权限 | 群信息、`bot_state` 等能不能调 | `11253` / `应用无接口访问权限` |
| **群管理能力 / 允许被添加** | 机器人资料卡、管理端 | 群里能做什么、能进哪些群 | 无（表现为 @ 不生效、机器人加不进群） |

> IP 白名单**设置后仅允许白名单内的 IPv4 地址**，且仅支持单个 IP、不支持网段。家用宽带出口 IP 一变就得补一条；这也是为什么有时昨天还能登录、今天就 401。

## 它能在什么时候提醒你

| 类型 | 说明 |
|---|---|
| 🔴 **开播** | 直播间从「未开播」变成「直播中 / 轮播中」（可带 @全体） |
| 🎬 **投稿** | 发布了新视频（按 BV 号判重） |
| 📝 **动态** | 发了新动态（按动态 ID 判重） |
| 📌 **置顶评论** | 在某条动态下置顶了评论 |

同一个 UP 主可按群、按类型分别开关——比如「A 群只要开播，B 群只要投稿」。此外还支持**合集订阅**。

### 不会重复打扰你

- **启动静默对齐**：每次启动先把订阅的当前状态记为基线，不翻历史内容补推；v2.3.6 按**真实写入回执**判定，宽限没完成不放行，登录态中途恢复会重新进入静默并强制对齐
- **删稿 / 撤稿不误推**：最新动态回退到更早一条时能识别并保持静默
- **置顶不重复推**：先按「新动态」推过、后来被置顶的，不会再以「置顶动态」推第二次
- **没有置顶评论是常态**：`-404 / 啥都木有` 记为一条空基线，不再每轮告警、也不会卡住启动宽限

## 安装

### 环境要求

- **Python 3.11**（Windows 商店版与官方版 3.11 均实测过）；其它版本未验证
- 依赖：`qq-botpy`、`aiohttp`、`PyYAML`、`Flask`、`playwright`。首次启动会自动安装，清单为纯 ASCII，中文 Windows 下不会再出现 GBK 解码报错
- `playwright` 装完**还要下载一次浏览器内核**：`playwright install chromium`（上百 MB，第一次慢是正常的；本机已有 Chrome / Edge 时可跳过）

### 方式 A：成品包（推荐，日常使用下这个）

去 **Releases** 下载 `OnO_Bilibili-Notifier[vX.Y.Z].zip`，**整包覆盖解压**，顶层目录固定是 `OnO_Bilibili-Notifier`。

> ⚠️ 不要只替换单个文件、不要叠旧补丁包。数据目录不在包内，覆盖不会动订阅、cookie、群备注和 `at_all_quota.json`。装完在面板按一次 **Ctrl+F5** 强刷，避免吃旧 CSS / JS 缓存。

双击根目录 **`启动机器人.bat`**。脚本会自己定位商店版 Python 的真身、检查残留进程、装依赖、拉起面板和机器人；`python` 命令别名失效（9009）不会影响它，也不会再误导你去改 AppID / AppSecret。面板地址：

```
http://127.0.0.1:8088
```

端口被占用会自动往后找空的，实际端口看控制台输出。

### 方式 B：源码 / fork

```bash
git clone https://github.com/OnOiduts/OnO_Bilibili-Notifier.git
cd OnO_Bilibili-Notifier

python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux / macOS: source .venv/bin/activate

pip install -r src/requirements.txt
python src/start.py
```

Windows 下也可双击 **`安装依赖.bat`**（装的是系统 Python，不会建虚拟环境）。

## 配置

配置有两条路，选一条即可。**推荐环境变量**，密钥不落盘。

### 方式一：环境变量 / `.env`（推荐）

```bash
cp .env.example .env
```

```ini
ONOBN_APPID=你的AppID
ONOBN_APP_SECRET=你的AppSecret
ONOBN_BILI_COOKIE=            # 可选，B 站登录 Cookie
ONOBN_DATA_DIR=               # 可选，数据存放位置
ONOBN_PANEL_PORT=             # 可选，面板端口，默认 8088
ONOBN_PANEL_PASSWORD=         # 可选，面板访问口令
```

**优先级：系统环境变量 > `.env` > `config.yaml`。** `.env` 已被 `.gitignore` 排除；提交前用 `git status` 确认一遍——真密钥推上去只能去开放平台重置 AppSecret。

### 方式二：面板填写

启动后到「🔐 凭据」填写，值会加密后存进 `config.yaml`（密文 + 同目录 `.machine_key`）。这只能防「顺手打开配置文件看到明文」，**不是真正的加密保护**；真想万无一失请用方式一。

### 去哪拿 AppID / AppSecret

1. 打开 [QQ 开放平台](https://q.qq.com) 扫码登录
2. 创建一个**机器人**（不是「应用」）
3. 进入该机器人 → **开发设置** → 复制 AppID / AppSecret
4. 把机器人拉进要推送的 QQ 群（沙箱阶段该群还需在**白名单群聊**里）

### 面板里几个容易混的设置

| 设置 | 作用 |
|---|---|
| **检查间隔（秒）** | 轮询**基线 / 起点**，撞风控从这里放慢 |
| **最快档（秒）** | 平稳后自动加快到的**下限**。想固定 12s 不加速，两个框都填 **12**（v2.3.6 起可在面板改，保存后下一轮即时生效） |
| **群备注** | 11253 未开通时给群起名字，替代「未命名群 N」 |
| **开播提醒 @全体成员 / 合并进卡片 / 测试也 @全体成员** | 见上文「平台新开放的群聊能力」 |
| **B 站登录** | 浏览器登录 / 手动粘贴 Cookie；有效期按「登录时刻 + 7 天」保守计算，第 5 / 6 天提醒并自动跑一次后台续期 |

> B 站 cookie 是服务端签发的，程序只能「制造一次续期机会」，换不换由 B 站决定；没换到新的会**保留原登录时刻**，不偷偷把提醒往后推。真失效（`-101`）时 headless 浏览器里同样是未登录，仍需人工扫码。

## 使用方法

### 三步跑起来

1. **填凭据** —— 🔐 凭据（或用 `.env`）
2. **登记群** —— 在 QQ 群里 **@ 机器人说句话**，群自动登记；也可在 订阅 → 登记群 手动粘 `group_openid`（登记后一律显示群名）
3. **加订阅** —— 订阅 → 添加订阅，填 UP 主 UID 或 B 站主页链接，勾选要提醒的类型

> 官方目前**没有「列出机器人所在群」的接口**，`group_openid` 只能从事件里拿，所以「群里首次 @ 才登记」是唯一可行的做法；面板列不出没交互过的群不是 bug。

### 面板能做什么

| 页面 | 功能 |
|---|---|
| 📊 概况 | 运行状态、立即检测、最近动态、一键备份 |
| 📋 订阅 | 群与订阅管理、按 UP 主 / 合集反查群、订阅迁移 |
| 🔐 凭据 | QQ 凭据、B 站登录（浏览器登录 / 手动粘贴 Cookie） |
| ⚙️ 设置 | 通用、图片、提醒开关、轮询节奏、@全体、数据与备份、安全、关于 |
| 📜 日志 | 运行日志（自动翻译成中文说明） |
| 🆕 更新日志 | 每个版本改了什么 |

群里 @ 机器人发「**测试**」可自检：它会先试主动发送，再用唯一一次被动回复机会把**真正结论**告诉你——是「能正常推送」还是「主动消息无权限」，不会只回一句误导的「成功」。

### 数据存在哪

默认在程序目录下的 `data`（配置、订阅、日志、备份、缓存、图片都在这）。想换位置：设 `ONOBN_DATA_DIR`，或到 设置 → 💾 数据与备份 里改。**整个 `data` 目录复制走就是完整备份**，面板「立即备份」也会打一份包。

## 排障索引

先看日志里的**错误码**，再按表定位；不要一上来就改凭据。

| 现象 | 关键码 / 关键词 | 去哪处理 |
|---|---|---|
| 启动脚本退出码 9009、`python --version` 空输出 | 商店版 Python 应用执行别名失效 | 新版启动脚本已直取 Appx 包里真身，无需修别名；确认日志出现 `Python 3.11.x` 即可 |
| `接口访问源IP不在白名单` | `11298` / `40023002` | 开放平台 → 开发设置 → IP 白名单，补当前公网出口 IP（仅单个 IPv4，不支持网段）；开加速器 / 换网络后会复发 |
| `主动消息无权限` | `40034105` | 群设置允许机器人主动发言、群里 @ 一下激活、确认在沙箱群名单里；用「测试」自检 |
| 连上后反复 `4009 Session timed out`、Windows 弹 `0xc0000142` | 网关会话超时 / `tasklist` 弹窗 | botpy 会自动重连，通常伴随 B 站接口抖动；v2.3.6 已改用 Win32 API 清残留进程，不再弹框 |
| 刚扫码却显示「cookie 未生效」 | 旧版瞬时 `bili_login` 误判 | v2.3.6 已修（连续 3 次才判失效、412 归回风控、换 cookie 即清旧标记）；去「凭据 → B站登录」当场求证 |
| 开机后疯狂补推停机期间的内容 | 启动基线没写入 | v2.3.6 按真实回执判定、登录态恢复后重对齐；别在满屏 404 / 502 时重启 |
| `-404 啥都木有` 刷屏 | 没有置顶评论的常态 | v2.3.6 已归为空基线，不再每轮 WARNING |
| 群名全是「未命名群 N」 | `11253` 未开通 | 面板「群备注」手动起名；或向平台申请白名单机器人权限 |
| 面板填了 12 却加速到 8s | 两个框含义不同 | 「最快档（秒）」也填 12 |
| 开播没 @全体 | 管理员 / 额度 / 测试开关 | 确认机器人是群管理员、当天没用过、正式开播开关已开；日志搜「@全体」看具体原因 |
| 面板页签切换时横向跳一下 | 旧版滚动条 | v2.3.6 已加 `scrollbar-gutter: stable`，装完 Ctrl+F5 |

完整错误码说明见面板日志页（自动翻译成中文）与 `docs/使用说明.md`。

## 维护政策与版本号规则

本项目已趋于稳定，此后**只接受两类改动**：① 功能更新（新增能力或对已有能力的实质增强）；② 严重 bug 修复（无法启动、数据丢失/损坏、推送完全失效、凭据泄露等）。措辞微调、纯观感调整、代码风格整理、性能优化、与上述两类无关的测试，一概不再改动。

版本号按下面这套走，不是「改一次 +0.0.1」：

| 改动类型 | 版本号变化 |
|---|---|
| 大更新 / 中等更新 | `+1.0.0` / `+0.1.0`，单独发版 |
| 小更新 | 攒够 **5 项** 才 `+0.0.1` |
| bug 修复 / 功能删除 | 攒够 **10 项** 才 `+0.0.1` |
| 两类合并 | 合计超过 **12 项** 也 `+0.0.1` |
| 严重 bug 修复 | 版本号**不涨**，末尾加 `fix`（如 `v2.3.6fix`） |
| 没做完 / 还在修的功能 | **不涨号**，实测确认没问题后才计入 |

**同一个问题只记一条**：同一个 bug 反复修几轮，日志里只保留首次那条，后续修复并入它的正文，不新增条目——日志要能一眼看出「改了什么」，不是「改了多少回」。v2.3.6 就是按这条规则把 v2.3.5 发布后累积的修复去重成 10 项发的。

> 举例：当前 `v2.3.6`，再出一个严重 bug 修复 → 下一个版本是 **`v2.3.6fix`**；再出第二次 → `v2.3.6fix2`。
